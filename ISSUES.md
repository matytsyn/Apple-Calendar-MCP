> Каждый пункт содержит статус, доказательство (файл:строка) и способ проверки.
> Пункт считается закрытым только после того, как исправление проверено командой из раздела «Проверка».

На этом Mac Swift-хелпер собран с Xcode 27.2. Все 119 тестов прошли.
Сервер apple-calendar зарегистрирован и включён в Codex CLI. Прямой вызов MCP
с этими настройками вернул 15 разрешённых календарей. В отдельном сеансе

## P1. High-уязвимости в зависимостях (безопасность)

**Статус:** исправлено
**Приоритет:** высокий
**Суть:** `npm audit --omit=dev` сообщает о high-уязвимостях:
- `body-parser@2.2.2` — DoS через неверный `limit` и trailing bytes.
- `fast-uri@3.1.2` — host confusion через backslash в authority.

Обе приходят транзитивно через `@modelcontextprotocol/sdk@1.29.0`
(`packages/mcp-server/package.json:27`) → `express@5` и `ajv`.

**Почему важно:** `SECURITY.md` прямо требует фиксировать версии зависимостей и
проводить аудит зависимостей.

**Что сделать:** обновить `@modelcontextprotocol/sdk` до версии без этих
зависимостей либо добавить `overrides` в корневой `package.json` на
исправленные версии `body-parser` / `fast-uri`.

**Проверка:** `npm audit --omit=dev` завершается без high/critical.

## P4. Полные заметки и детали событий хранятся в локальной БД (безопасность/приватность)

**Статус:** принято и задокументировано
**Приоритет:** средний
**Суть:** для отката в `rollback_operations` пишется полное состояние события:
`title`, `notes`, `location`, `url`, `timezone`, `start`, `end`.
См. `packages/calendar-service/src/rollback-service.ts:380-392` и `:618-630`.

**Почему важно:** `SECURITY.md` (Audit Logging / Data Minimization) требует
«Avoid storing full notes» и минимизацию. Здесь эти данные реально лежат
в `~/Library/Application Support/AppleCalendarMCP/state.sqlite`.

**Решение:** полное состояние сохраняется для точного отката и явно описано в
`SECURITY.md` как принятый риск. Компактные ответы инструментов не возвращают
приватное содержимое.

**Проверка:** решение отражено в `SECURITY.md`; тест не фиксирует утечку
заметок в ответах инструментов.

## P5. Путь к хелперу и БД управляется переменными окружения (безопасность, принятый риск)

**Статус:** принято и задокументировано
**Приоритет:** низкий/средний
**Суть:** `APPLE_CALENDAR_MCP_HELPER`, `APPLE_CALENDAR_MCP_DATABASE_PATH`,
`APPLE_CALENDAR_MCP_CONFIG_PATH`, `APPLE_CALENDAR_MCP_HELPER_LAUNCH_MODE`
читаются из окружения
(`read-service.ts:683-689`, `write-service.ts:1024-1025`,
`rollback-service.ts:588-589`, `:844`).

Для локального сервера это разумно, но процесс, способный менять env
MCP-клиента, может подменить хелпер/БД.

**Решение:** риск описан в `SECURITY.md` в разделе Threat Model → Local Abuse.

**Проверка:** раздел в SECURITY.md присутствует.

## P6. Unix-сокет хелпера без проверки peer-идентичности (безопасность, принятый риск)

**Статус:** открыто
**Приоритет:** низкий
**Суть:** защита сокета — только права каталога (`mkdtemp`, 0700).
Нет `getpeereid`/проверки аудит-токена на стороне Swift-хелпера.
См. `packages/calendar-service/src/eventkit-bridge-client.ts:166-211`,
`apps/macos-helper/Sources/main.swift:107-187`.

Для локального сценария приемлемо; ужесточение — проверка UID пира.

**Что сделать:** по желанию добавить `getpeereid` в Swift-хелпере или
зафиксировать риск в SECURITY.md.

## Что уже проверено и признано корректным

- SQL параметризован (`prepare(...).run(?, ?)`), конкатенации в запросах нет:
  `packages/sqlite-store/src/store.ts`.
- Токены подтверждения хранятся как SHA-256-хэши:
  `packages/calendar-service/src/write-service.ts` (`sha256(confirmation_token)`).
- Слои проверок записи: режимы `read_only`/`ask_before_write`/`trusted_write`/
  `full_write`, allowlist, confirm-гейт: `write-service.ts`
  (`permissionModeFailure`, `verifyConfirmation`).
- Логи в stderr, stdout только для протокола MCP: `packages/mcp-server/src/logger.ts`,
  `index.ts`.
- Shell-скрипты без незакавыченных переменных; запуск процессов через
  `spawn(command, args)` без shell-строки.
- `SECURITY.md` описывает правильную модель угроз.
